# スクリプトの依存関係について

作成日: 2026年8月

## いまの構造

```
Core          入力の読み取り口・プレイヤーの状態・計算・使い回しの置き場
                 → 誰にも依存しない

Presentation  演出と音（画面のひと光り・ヒットストップ・BGM・カットイン）
                 → Core のみ

Player        犬の操作・技・カメラ
UI            画面の表示
                 → 互いに依存しない
```

`Core` と `Presentation` には asmdef を付けてある。
まとまりとして名前が付いているので、参照できる先が設定で固定される。

## 解決済み: Player と UI の循環

以前は次の形で絡んでいた。

```
Player → UI   技が画面のボタンを読み、演出を鳴らしていた
UI → Player   ボタンや表示がプレイヤーの中身を直接読んでいた
```

3つの手を打って解いた。

**1. 入力を集約した**

キーの直読みが20ファイルに散っていた。
割り当てを `Assets/Resources/ProjectKMP.inputactions` へ集め、
`Core.GameInput` を唯一の読み取り口にした。

画面のボタンは `TouchControls` が毎フレーム `GameInput.PushTouch` で押し込む。
読む側はどこから来た入力かを知らなくてよくなった。

**2. 演出を別の層へ出した**

`ImpactFrame` `BgmPlayer` などは誰にも依存しない『呼ばれるだけ』の処理だった。
`Presentation` へ移したことで、Player からも UI からも同じように使える。

**3. 状態を Model 経由にした**

`Core.PlayerStatus` に体力・技の待ち時間・注目している相手などを持たせ、
Player が書き込み、UI が読む形にした（R3 の ReactiveProperty）。

UI はプレイヤーを探し回らなくてよくなり、
ネットワークで遅れて生まれる相手を待つ必要もなくなった。

## 未解決: Battle / Monster / Gorilla の循環

```
Battle  → Player, Monster, Gorilla
Monster → Battle
Gorilla → Player
Player  → Battle, Monster, Gorilla
```

3者が絡んでおり、asmdef を付けられない。

**手を付けていない理由**

ボスの実装は別の担当が進めているため。
勝手に構造を変えると、そちらの作業とぶつかる。

**解くとしたらの方針**

Player と UI で使った手がそのまま当てはまると考えている。

- **ボスの状態を Model へ出す**
  体力・残りの本数・いまの行動を `Core` に置き、
  UI と Battle はそこから読む。`Monster → Battle` が消える。

- **戦いの進行を Model へ出す**
  『戦闘中か』『クリアしたか』を `Core` に置く。
  `BattlePlayGate` が既に近い役割を持っているので、そこを育てる形になる。

- **ボスの行動から Player を直接見ない**
  いまは `Gorilla → Player` で相手を探している。
  『狙う相手』を渡す形にすれば向きが消える。

**先に測ること**

どれくらいの規模かは、次で調べられる。

```
Assets/Contents/Scripts の各フォルダについて、
他フォルダの名前空間を using している箇所を数える
```

Player と UI のときは、最終的に残った本当の依存は5行だけだった。
見た目より小さいことが多いので、まず数えるところから始めるとよい。

## 分割のときに気をつけること

**asmdef を付けると、使う道具を明示する必要がある。**
`Core` に Input System と R3 を書き忘れて、型が見つからないエラーが出た。

**シーンやプレハブの参照は名前空間を変えても切れない。**
Unity は GUID で覚えているため。ただし手で書いた `using` は直す必要がある。

**使っていない `using` が依存に見える。**
消してコンパイルが通れば、本当に要らなかったと分かる。
Player と UI では、12件のうち7件がこれだった。
